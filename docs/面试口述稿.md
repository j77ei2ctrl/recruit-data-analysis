# 项目口述稿 · 2 分钟版

> **适用场景**：面试开场"介绍一下你的项目"、技术面项目深挖环节。
> **听众画像**：企业大数据 / 数据处理岗面试官——他们不缺"会用 pandas 分组统计"的人，缺的是**知道结论在什么条件下成立**的人。
> **讲述重心**：数据质量判断 > 方法严谨性 > 结论本身。结论只是结果，判断过程才是能力证明。

---

## 一、正式版（约 2 分 05 秒，589 字）

> 语速控制在每分钟 270–290 字。**加粗处放慢、略作停顿**，那是面试官记笔记的地方。

### 【0:00–0:15】定位：一句话说清是什么

我做了一个求职决策分析项目，用 1.4 万条招聘数据回答一个问题：**专科应届生想进大数据方向，该学什么、投哪里、第一份工作从哪切入。**

一句话结论是——**方向值得选，但不能指望毕业直接投进去。**

### 【0:15–0:52】数据与清洗：体现工程严谨

数据是和鲸社区公开的拉勾数据集，原始 2.1 万条、21 字段，清洗后 1.47 万条、59 列。

清洗里有两件事我想重点说：

第一，薪资是"20k-35k"这种字符串，**我没有用 IQR 机械剔异常值**，而是按业务含义分类。上限小于下限、月薪过十万疑似年薪误填的，直接剔；区间跨度过大或低于 3K 的，打标保留，后面用两套口径跑敏感性检验，验证结论稳不稳。

第二，按岗位 ID 去重删了 31%，**这个比例反常，我先验证了再删**：3568 个重复组里跨城市重复是 0 组、组内薪资 100% 相同，确认是重复采集，这才动手。

### 【0:52–1:28】关键发现：反直觉的那两个

我认为最有价值的，是**先发现了数据本身的偏差**。70 个类别里有 33% 的记录数挤在 440 到 450 之间；而现实中 Java 的岗位量是 Perl 的几十倍，这里两者却几乎一样多。所以判断它是"每类封顶约 450 条"的采样，**所有占比类结论我全部改成"样本内占比"**，不做市场规模排名。

第二个是技能溢价的反转。全样本看，要求 Spark 的岗位薪资高 6.5K、35%；但把城市等级、工龄、岗位方向固定住再比，**差值变成负 2.5K**。那 35% 不是 Spark 值钱，是数据开发岗本身薪资高——**在这个岗里 Spark 是标配，不是稀缺项**。

### 【1:28–1:58】结论：落到可执行

结论四条：大数据岗薪资中位数 22.5K，确实高于后端开发的 19K；但 577 个大数据岗里，**专科加应届只剩 5 个**，严格口径是 0。

所以我现在的投递策略是——先投数据运维、ETL、后端开发这些**技能栈重叠**的岗位，两年后带着真实数据处理经验再转。技能按 Hive + Spark 这个组合学，因为 30% 的岗位同时要求这两个。城市优先广州、成都，学历门槛比北京低三倍，薪资只差 5 到 7K。

### 【1:58–2:05】收尾

这个项目对我最大的价值，不是画了四张图，是**学会了先质疑数据、再相信结论**。

## 二、30 秒电梯版（约 130 字）

> 用在"简单说说"、群面、或者面试官赶时间的时候。

我做了一个求职决策分析项目，用 1.4 万条招聘数据算清楚三件事：大数据方向薪资中位数 22.5K，比后端高 3.5K，值得进；但专科加应届三重条件筛下来只剩 5 个岗位，所以第一份工作要先走数据运维、ETL 这类技能相邻的岗；技能按 Hive 加 Spark 的组合学，因为 30% 的岗位同时要这两个。

## 三、必须记住的 6 个数字

> 讲错数字比讲不出数字更致命。这 6 个是全场只可能被追问的核心值。

| 数字 | 含义 | 追问时会用到 |
| :--- | :--- | :--- |
| **21,320 → 14,725** | 原始条数 → 清洗后条数 | 数据规模、清洗力度 |
| **31%** | 去重删除比例 | 为什么删这么多、怎么证明删对了 |
| **22.5 K / 19.0 K** | 大数据岗 / 后端开发薪资中位数 | 方向价值 |
| **+37.9 pp** | Hive 在大数据岗与全体岗的命中率差值 | 技能区分度 |
| **+6.5 K → −2.5 K** | Spark 溢价（全样本 → 控制混淆变量后） | 相关不等于因果 |
| **5 个 / 0 个** | 专科+大数据+应届可投（宽口径 / 严格口径） | 现实机会量 |

## 四、被打断时的三种接法

面试官经常在中间插话，**不要慌着讲完，跟着他的问题走**——他问的地方就是他关心的能力项。

### 打断 ①「等一下，你为什么不用 IQR 剔异常值？」

> **接**：因为机械剔除会把真实的高薪岗误删。技术岗薪资右偏很严重，P90 是 P37.5 的两倍多，IQR 规则会把一批真实的 40K 以上岗位当异常值干掉。我改成按业务含义分类——真正错的是"上限小于下限"和"月薪十万以上"这两类，其余打标保留，再做两套口径对比。**中位数在两套口径下完全一致，说明结论不受影响。**

### 打断 ②「1.4 万条太少了，能代表市场吗？」

> **接**：代表不了市场规模，我在报告里明确写了这一点。它的问题是**按类别封顶采样**，所以任何"某类岗位占百分之几"的结论都不成立，我全文只用"样本内占比"这个口径。但它对我要回答的问题够用——我要比的是**类别内部**的技能要求和薪资结构，那部分样本量是充足的，大数据岗有 582 条。

### 打断 ③「你这个结论网上到处都是，有什么新东西？」

> **接**：前三条确实不新。真正不一样的是第四条——**技能本身不构成溢价**。网上普遍的说法是"学 Spark 能涨薪"，我做了分层控制之后发现是 −11%。这个反转意味着简历上写"精通 Spark"没用，写"我用 Spark 把报表产出从 4 小时压到 2 分钟"才有用。**这一条改变了我写简历的方式。**

## 五、反向提问（收尾时问，很有加分）

讲完项目后如果面试官问"你有什么想问的"，可以顺着项目问：

1. 团队现在的数据体量大概在什么量级？主要痛点是**数据质量**还是**链路效率**？
2. 如果我进来，第一个月最可能接到的是哪类任务——报表开发、ETL 维护，还是链路的稳定性？
3. 团队里做数据开发的同学，通常是从哪个岗位转过来的？（**这题能侧面验证我"曲线进入"的策略对不对**）

## 六、讲述纪律

| ✅ 要做 | ❌ 不要做 |
| :--- | :--- |
| 先说结论，再说过程 | 从"我用了 pandas 的 read_csv"开始讲 |
| 主动说局限和口径 | 等面试官挑出问题才解释 |
| 数字说"中位数" | 说"平均薪资"（会被追问右偏） |
| 用"我判断 / 我验证 / 我改成" | 用"我们"（个人项目说"我们"会被怀疑） |
| 停在结论上 | 把所有分析表挨个念一遍 |
