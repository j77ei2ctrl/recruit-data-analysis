# 大数据招聘岗位数据分析

> 用 108 条**四川本地真实招聘岗位**数据，回答一个专科应届生最关心的问题：
> **我到底能投什么岗？能拿多少钱？**

## 一句话结论

> 四川大数据岗位**机会很多，但集中在地板价的数据加工环节**。
> 算法岗中位数 ¥25,000，专科可投的岗位数量是 **0**；
> 专科能投的岗位中位数只有 ¥4,250，差 **5.9 倍**。
> **学历卡住的不是入场券，是天花板。**

## 数据清洗踩过的坑

真实数据不会自己变干净。以下 6 个问题都在清洗中逐个处理，代码见 `scripts/01_clean_data.py`：

| 问题 | 表现 | 处理 |
|---|---|---|
| **编码带 BOM** | 首列名变成 `\ufeffjob_id`，列名匹配失败 | 用 `encoding='utf-8-sig'` 读取 |
| **福利字段污染** | `welfare` 混入薪资文本（`10000-12000`）和制表符 | 分隔符切分 + 正则剔除数字条目 |
| **经验缺失 51.9%** | 56 条为空 | **不删样本**，标记「未说明」；空值本身代表「要求不高」 |
| **学历 11 种写法** | 职高/初中/中专/大专/本科… | 归并为 2 组 / 6 级两套口径 |
| **岗位名 90+ 种** | 命名五花八门 | 关键词规则归类，**规则顺序敏感** |
| **薪资口径风险** | 需防年薪日薪混入 | 校验 `salary_text` 含「月」，确认 100% 月薪口径 |

> **规则顺序为什么敏感**：如果先匹配「开发/工程」，`数据标注工程师` 会被误归入数据开发岗——标注类会被系统性低估。所以标注、采集、质检必须优先判断。

## 诚实声明：这些我没做

本项目有几件事**刻意没做**，因为数据不支持，做了就是编造：

| 没做的事 | 原因 |
|---|---|
| ❌ **技能需求词频分析**（如「SQL 要求占比 82%」） | 采集字段**不含岗位 JD 正文**，没有技能标签。仅凭岗位名称做词频统计，结果无法回答「你统计的哪来的」 |
| ❌ **因果推断**（「学历导致薪资低」） | 108 条数据只能证明**相关性**。准确表述是「学历门槛不同的岗位，薪资分布差异很大」 |
| ❌ **全体应届生的结论** | 样本仅 108 条、单一平台、单一时间截面，只代表该平台当时的岗位结构 |

面试时这两点反而是加分项——**知道什么不该做，比会做什么更重要**。

## 关于样本量（常被追问）

只有 108 条，能说明什么？

**它能回答的问题**：这个平台上，专科生能投什么岗、薪资大概什么水平、学历门槛卡在哪。看的是**结构**，不是精确均值。

**它不能回答的问题**：整个四川就业市场的薪资水平。公共招聘平台偏向中小企业和基础岗位，会**低估**高薪岗位比例。

方向上是**保守**的：如果连偏低门槛的渠道都只有 54.6% 可投、中位数 4,250 元，那真实情况不会更好。
